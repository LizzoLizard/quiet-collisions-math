The result

Let Q : F2n → F2n have coordinates of algebraic degree at most k. Suppose its output on a uniform input is d-wise uniform (every Walsh coefficient on a nonzero mask of weight ≤ d vanishes), but Q is not a bijection. Counting ordered collisions C(Q) = #{(x, x′) : Q(x) = Q(x′)},

min (C(Q) − 2n) = 2max(⌈n/k⌉, d+1)

for every k ≥ 1 and 0 ≤ d < n

For compressing maps Q : F2n → F2m with 1 ≤ m ≤ n,

min (C(Q) − 22n−m) = 2max(2⌈n/k⌉ − m, ⌈n/k⌉, d+1)

for every k ≥ 1 and 0 ≤ d < m; the answer jumps once m drops below ⌈n/k⌉

Both lower bounds are classical: Delsarte's support bound gives 2d+1, and McEliece-type divisibility of degree-k signed sums gives 2⌈n/k⌉. The contribution is that the larger of the two is always attained, by an explicit ring of gates with up to k−1 control bits on each edge, and the exact answer for compressing maps. The stretching case m > n remains open.

In plain words

Take a rule that scrambles n-bit strings into n-bit strings using simple polynomial formulas. If the rule never sends two inputs to the same output, its output on a random input is perfectly random. Now ask for less: the output only has to look perfectly random when you inspect any d output bits at a time. Such a rule can have collisions. The theorem says exactly how few collisions it can get away with, and gives a construction that achieves it.

How it is checked

  • A complete Lean 4 proof of both exact minima, using only Lean's core (no Mathlib), with no sorry and only the standard axioms propext, Quot.sound and Classical.choice. Lower bounds hold for every eligible map; the attaining maps are checked for degree, uniformity and collision count.
  • A Challenge/Solution comparator check: the two statements and every definition they use are collected in two short files, and the proofs must match them exactly.
  • Independent Python checks: hundreds of ring constructions checked in every bucket and mask, and exhaustive enumeration of all eligible maps in small cases.
theorem exact_minimum (n k d : Nat) (hk : 0 < k) (hd : d < n) :
    Attainable n k d (many (max ((n+k-1)/k) (d+1))) ∧
    ∀ value, Attainable n k d value → many (max ((n+k-1)/k) (d+1)) ≤ value

Clone the repository, install Lean 4.15.0, Python 3 and NumPy, and run ./verify.sh (under a minute). GitHub Actions runs the same check on every push.
